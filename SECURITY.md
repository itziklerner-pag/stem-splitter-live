# Security Policy

## Reporting a vulnerability

**Please do not open a public issue for a security problem.**

Report it privately through GitHub's
[Security Advisories](https://github.com/itziklerner-pag/stem-splitter-live/security/advisories/new),
or by email to **security@stemsplitter.live**.

Please include what you did, what happened, what you expected, and your Chrome
version. A proof of concept helps but is not required to file.

**What to expect:**

| | |
|---|---|
| acknowledgement | within 72 hours |
| initial assessment | within 7 days |
| fix or a plan with dates | within 30 days for anything we accept |
| public disclosure | coordinated, and no later than 90 days after the report |

This is a small project run by volunteers. If a deadline is going to slip we
will tell you rather than go quiet. You will be credited in the advisory and the
changelog unless you would rather not be.

## Supported versions

The most recent release. There are no long-term support branches.

## Scope

A browser extension that can hear a tab's audio has a larger blast radius than
its size suggests. In scope:

- Anything that lets a web page, another extension, or a remote party start,
  read, or persist a capture the user did not initiate.
- Anything that causes audio, page content, or user data to leave the machine.
- Escaping the deck iframe's extension origin, or reaching `chrome.*` APIs from
  page context.
- Persisting capture past teardown, or a state where a tab is left permanently
  muted with no way to recover it.
- Model-supply-chain issues: anything that would let modified weights pass the
  SHA-256 pin, or that lets the pin be redirected.

### Three project rules are security properties, and breaking one is a vulnerability

These are not stylistic preferences. A regression in any of them is a valid
report, and we will treat it as such even if nothing is "exploitable" in the
conventional sense.

- **No network after the model download.** The extension must complete a full
  session with every network interface disabled. Any code path that opens a
  socket — telemetry, analytics, error reporting, a font, an update ping — is a
  finding.
- **No remote code.** The ONNX Runtime binaries and model weights are fetched as
  *data* and hash-verified. Any path that executes fetched content as script, or
  that injects a script tag pointing at a remote host, is a finding.
- **Capture only what the user's own player renders.** Audio comes from
  `chrome.tabCapture` and nothing else. Any code that resolves, fetches, or
  parses a media stream URL is a finding — both because it is a policy breach
  and because it is a class of code that has no legitimate reason to exist here.

## Out of scope

- The 109 MB model download itself being observable on the network. It is a
  plain public file fetch and is documented as such in
  [`PRIVACY.md`](PRIVACY.md).
- Vulnerabilities in Chrome, in ONNX Runtime Web, or in the model — report those
  upstream. We will help you route it and will pin a fixed version once one
  exists.
- The tab going silent while capture is active. That is how `chrome.tabCapture`
  works: holding the media track *is* the mute. A tab left silent *after*
  teardown is in scope.
- Anything requiring the attacker to already have local access to the machine,
  or requiring the user to install a malicious extension alongside this one.
- Reports generated by a scanner with no analysis of whether the finding is
  reachable in this codebase.

## Safe harbour

We will not pursue or support legal action against anyone who reports in good
faith, follows this policy, and does not access, modify, or exfiltrate other
people's data while testing. Test against your own browser and your own content.

There is no bug bounty. There is no money in this project.
